# Планировщик жизни (рабочее название)

Личный сайт-планировщик для одного пользователя (Ваня). Вырос из трекера «Копилка на Турцию».
Пользуюсь с компьютера и телефона. Аккаунт нужен только для синхронизации между устройствами — без входа всё работает локально.

## Стек
- Vite + React + TypeScript
- Данные: localStorage + кнопки «Экспорт / Импорт JSON» для бэкапа
- Синхронизация (по желанию): Supabase — вход по email+паролю, одна строка на пользователя в таблице `planner_data`. Своего бэкенда нет
- Стили: обычный CSS (модули), без тяжёлых UI-библиотек
- Шрифт Manrope (`@fontsource/manrope` — лежит в сборке, работает офлайн), иконки `lucide-react`
- PWA: `vite-plugin-pwa` — сайт ставится на телефон как приложение и работает офлайн

## Структура
- Сверху переключаемые вкладки: «Сегодня» (открывается по умолчанию), «Деньги», «Неделя», «Смены», «Привычки». На узком экране выбранная вкладка сама прокручивается в видимую часть полосы
- `src/tabs/` — по папке на вкладку (`today/`, `money/`, `week/`, `shifts/`, `habits/`)
- `src/storage/` — вся работа с localStorage в одном месте (компоненты не трогают localStorage напрямую)
- `src/types.ts` — общие типы данных
- `src/styles/tokens.css` — дизайн-токены, `src/styles/global.css` — сброс, шрифт, фокус
- `src/components/ui/` — единые компоненты интерфейса (Button, Card, Collapsible, Input, Select, Textarea, ProgressBar, Badge/StatusDot)
- `src/sync/` — синхронизация с облаком (`syncEngine.ts` — вход, отправка/загрузка, статус; `syncLogic.ts` — решения без сети; `sections.ts` — разделы данных; `supabaseClient.ts`); `src/components/sync/` — статус в шапке, панель аккаунта, вопрос «какие данные оставить»
- `supabase/migrations/` — SQL таблицы и политик RLS, `supabase/tests/rls_check.sql` — проверка RLS (запускать в SQL Editor)
- `private/` — личные файлы (настоящие выписки для тестов). В `.gitignore`, никогда не коммитим. Тестовые PDF брать только отсюда

## Дизайн
Тёмный «космический» стиль, единый для всего сайта: почти чёрный фон с туманностью, поверх — тёмные карточки со светлой рамкой и мягким свечением, бирюзовый акцент, один спокойный шрифт Manrope. Главное — читаемость: сайт смотрят с телефона после ночной смены. Скриншоты в `docs/screenshots/` — старый (светлый) дизайн, ориентир только по раскладке.

**Токены — единственный источник значений**
- Все цвета, отступы, радиусы, размеры шрифта, свечение и анимации — только `var(--…)` из `src/styles/tokens.css`. Никаких hex/rgb «на месте» в компонентах. Нужен новый цвет — добавь токен
- Отступы — шаг 4/8 px: `--space-1` (4) … `--space-12` (48). Произвольных `13px` нет
- Радиусы: `--radius-sm` (6 — клетки сеток, квадратики дней), `--radius-md` (14 — плитки внутри карточки, поля), `--radius-lg` (20 — карточки), `--radius-full` (кнопки, чипы, вкладки)

**Тема — только тёмная** (переключателя нет, `color-scheme: dark`)
- Фон `--color-bg` #08080c + «туманность» (`src/components/Backdrop`): три размытых пятна — бирюзовое `--nebula-teal` вверху слева, фиолетовое `--nebula-violet` справа по центру, синее `--nebula-blue` внизу (`--nebula-opacity` 0.18, `--nebula-blur` 85px) + редкие мелкие звёзды. Фон неподвижный (`position: fixed`, `z-index: -1` внутри `#root` с `isolation: isolate`), контент прокручивается поверх
- Шапка полупрозрачная (`--color-header` + размытие)

**Палитра**
- Поверхности: карточки `--color-surface` #1a1a1d, плитки внутри карточки и поля `--color-surface-muted` #232327, выбранный сегмент `--color-surface-raised`; рамки `--color-border` rgba(255,255,255,0.14), `--color-border-strong` rgba(255,255,255,0.35); текст `--color-text*`
- Акцент — бирюза `--color-accent` #26b5a6, текст на акценте `--color-on-accent` #0b2a27; `--color-today` (белый) — обводка «сегодня»
- Пропуски и перерасход — коралловый #ffb4a8 (`--status-missed-*`, `--status-danger-*`), **всегда со значком ✕ или «!» и подписью**, не только цветом (`Badge` с тоном missed/danger ставит значок сам)
- Отгул — фиолетовый (`--status-leave-*`), выходной — голубой (`--status-off-*`), смена — в тон акцента (`--status-shift-*`), положительные суммы — `--status-success-fg`
- Нельзя: кислотные цвета, эмодзи в интерфейсе, свечение и тени на кнопках

**Типографика** (у всех цифр `tabular-nums`)
- Один шрифт на всё — Manrope (`--font-sans`), иерархия только размером и жирностью. Pixelify Sans и JetBrains Mono больше не используем: у пиксельного шрифта плохая кириллица, моноширинный в мелком тексте читается тяжело
- Заголовки и крупные цифры (итоги, «Можно потратить», остатки) — 800; заголовки карточек — 700; обычный текст — 400–500; кнопки и подписи значений — 600
- Размеры: заголовок раздела `--text-lg` (22), заголовок карточки `--text-md` (17), текст `--text-base` (14), подсказки `--text-sm` (12, `--color-text-muted`), мелкое `--text-xs` (12). Крупные числа — `--text-xl` (32), на телефоне в плитках по две в ряд — `--text-lg`
- Все подписи — обычным регистром, КАПС не используем (исключение — двухбуквенные дни недели ПН…ВС). Мелкий текст не меньше 12 px, цвет подсказок `--color-text-muted` не темнее #9a9aa2 (контраст на фоне карточки ≥ 4.5:1); `--color-text-subtle` — только плейсхолдеры, выполненное и значки

**Компоненты** — новые экраны собираются из `src/components/ui`, свои кнопки/поля не делаем
- `Card`: `--color-surface`, радиус `--radius-lg`, рамка `--color-border` + мягкое свечение `--glow-card` (0 0 22px rgba(255,255,255,0.07)); заголовок, подзаголовок, действия справа; `compact` для списков карточек. Внутренние плитки (итоги, остатки, итог недели) — `--color-surface-muted`, `--radius-md`, без рамки
- `Button` — «таблетки», **без свечения**: `primary` — заливка акцентом, одно главное действие в форме; `secondary` — прозрачная с рамкой `--color-border-strong`; `text` — тихие («Изменить», «Отмена», удаление). Размеры `sm`/`md`. Кнопка-иконка — `iconOnly` + обязательный `aria-label`. Переключатель — `aria-pressed` (бирюзовая рамка и фон)
- `Collapsible`: свёрнутая карточка (`<details>`) того же вида, заголовок + подзаголовок видны всегда, содержимое по клику; `id` — чтобы раскрыть кодом
- `Input`: подпись сверху, подсказка/ошибка снизу; без подписи — нужен `aria-label`. У числовых полей `step="1"` (иначе браузер молча не отправит форму с «неровным» числом)
- `Textarea`: многострочное поле в стиле Input, подпись сверху, растягивается вниз
- `Select`: выпадающий список в стиле Input, размеры `sm`/`md`; `className` задаёт ширину обёртки
- `ProgressBar` (`tone="danger"` — превышение, коралловым), `Badge` — контурный чип (тона neutral/accent/shift/missed/leave/off/danger), `StatusDot` для кнопок выбора статуса
- Прогноз «Успеваешь / Впритык / Не хватит» (`ForecastPhrase`) — контурный чип с точкой-индикатором (бирюзовая / серая / коралловая + «!»)
- Квадратик дня `DaySquare` (`src/tabs/shifts/`) — один вид для календаря смен, мини-недели и серии смен (`dayMark` из `schedule.ts`): отработал — заливка акцентом, смена впереди (и сегодня) — контур акцентом, «не вышел» — коралловый со значком ✕, отгул/выходной — свои цвета, сегодня — белая обводка. Легенда — `DayLegend`
- Иконки lucide 12–18 px, только где помогают понять действие или статус (стрелки, добавить, удалить, закрыть, бэкап, ✕/«!» у пропусков)

**Раскладка и поведение**
- Шапка: название слева (под ним мелко — статус синхронизации), вкладки-«таблетки», справа бэкап (кнопки-иконки с подсказкой) — на компьютере в одну строку. На узком экране (≤ 640 px): название и кнопки — первая строка, вкладки — вторая на всю ширину и прокручиваются по горизонтали
- Контент по центру, ширина не больше `--content-max-width` (880 px), между карточками `--space-4`, внутри карточки `--space-6`
- Hover/focus — плавно, `--transition-fast` (150 мс). Фокус с клавиатуры всегда виден (`:focus-visible`, рамка `--color-focus`)

## Вкладки версии 1
### Сегодня (`src/tabs/today/`)
Главное на один экран: на компьютере (1280×800) — без прокрутки, две колонки (слева день и деньги, справа задачи, привычки, неделя); на телефоне — одна колонка в порядке ниже. Своих данных нет, только собирает чужое — логику не дублируем (`todayLogic.ts`):
1. Статус дня (смена / не вышел / отгул / выходной / смены нет) и что дальше: «Завтра смена» или «Ближайшая смена — …» (`getEntry`/`findNextShift` из `schedule.ts`)
2. Деньги: «Турция: X из Y ₽», прогноз одной фразой (`turkeyForecast` + `ForecastPhrase`) и «Можно потратить» (`spendable`). Кнопка «Получил за смену»: сумма + смена (по умолчанию последняя отмеченная смена без дохода, иначе сегодня — `defaultIncomeShiftDate`), после ввода сразу раскладка 50/40/10 с галочками «Перевёл». Те же компоненты и логика, что в «Деньгах»: `IncomeForm`, `IncomeShares`, `addManualIncome`/`toggleTransfer`/`markShiftsByIncome` из `moneyLogic.ts`
3. Напоминания: непереведённые доли дохода (`pendingTransfers`) — галочка ставит ту же отметку «Перевёл», что во вкладке «Деньги». Нет долей — карточки нет
4. Задачи на сегодня — те же, что в «Неделе» (`planner.week`, `addTask`/`toggleTask` из `weekLogic.ts`): галочки и быстрое добавление
5. Привычки на сегодня — отметка в один клик (те же данные, что во вкладке «Привычки»), рядом «N подряд»; в подзаголовке — лучшая текущая серия (`bestStreak`, с автопривычкой); автопривычка «Смены без пропусков» — строкой текста и полоской из 14 квадратиков (`ShiftStreakStrip`)
6. Мини-неделя пн–вс: квадраты дней как в календаре «Смен» (`DaySquare`), сегодня в белой рамке, без подписей статуса (статус — во всплывающей подсказке и для экранных чтецов)

### Привычки (`src/tabs/habits/`)
- По умолчанию: «30 минут кода», «Английский», «Лёг вовремя». Можно добавлять, переименовывать, убирать в архив и возвращать (отметки сохраняются)
- У каждой — текущая серия дней и рекорд, сетка за последние 8 недель (колонка = неделя, строка = день с понедельника). Клик по клетке прошлого дня ставит/снимает отметку (если забыл)
- Серия: дни подряд с отметкой. Сегодня ещё не отмечено — серия со вчера жива. Не отмечено ни сегодня, ни вчера — серия 0 и «Начни новую серию». Без красных «провалов»: неотмеченный день — просто нейтральная клетка
- Автопривычка «Смены без пропусков» не хранится и вручную не отмечается: считается из «Смен» — смены подряд без «не вышел» (дни без смены серию не прерывают; сегодняшняя смена ещё не считается, «не вышел» сегодня — уже пропуск). Вместо сетки за 8 недель — серия смен: 14 квадратиков за последние 2 недели (`ShiftStreakStrip`, `lastDays`), сегодня в белой рамке
- Логика — `habitsLogic.ts` (без React). Хранение: `planner.habits` = `{ habits: [{ id, name, archived }], marks: { id: ['YYYY-MM-DD', …] } }`

### Деньги (`src/tabs/money/`)
Два режима — кнопки «Турция | Месяц» вверху, справа шестерёнка «Настройки». Внизу в обоих режимах — зона «Перетащи PDF выписки сюда или выбери файл».

**Счета.** Карта (основной счёт: доход за смены, траты) + 3 накопительных счёта-конверта: «Жизнь», «Турция», «Одежда и уход». Конверты настоящие: после каждого дохода доли переводятся на эти счета. Остальные счета — «Другой» (не учитываются)
- Счёт в выписке определяется по номеру лицевого счёта («Номер лицевого счёта: № …»). Знакомый — тип запомнен; новый — в предпросмотре спрашиваем, какой это (Карта / Жизнь / Турция / Одежда и уход / Другой), и запоминаем в `accounts`. Тип можно поменять в настройках. Тип по содержимому выписки (`parsed.kind`) — только подсказка
- Остатки счетов: из выписок («Входящий остаток» = на конец дня перед периодом, «Исходящий») + операции между ними (`balanceOf` в `moneyLogic.ts`); можно ввести остатки вручную («Ввести остатки», на сегодня) — введённый новее выписки главнее, операции после него прибавляются
- Переводы между своими счетами — не траты и не доходы

**Доход за смену** = 2 платежа «Оплата за усл. по дог.» на карту: аванс через 1–2 ч после начала и основная сумма ~12:00 следующего дня. Платежи с 18:00 дня D до 18:00 D+1 → смена D (`shiftDateOfPayment`). Пришёл доход, а смена не отмечена — при загрузке выписки карты (и при вводе «Получил за смену») день отмечается «Смена»; отмеченные дни не трогаем
- «Получил за смену» вручную — по желанию (`manualIncome`), то же поле есть на «Сегодня»; дата смены по умолчанию — последняя отмеченная смена без дохода (`defaultIncomeShiftDate`); дата поступления у ручного дохода — день после смены (основная выплата ~12:00). Выписка карты дополняет недостающие доходы и сверяет введённые: «сходится» / «из выписки» (добавлено) / «проверь» (расходится — берётся выписка, введённое можно убрать). Дублей нет: ключ — дата смены
- После дохода (смены с даты старта): «Переведи X на Жизнь, Y на Турцию, Z на Одежду и уход» (50/40/10, настраивается) с галочками «Перевёл» (`transfers`). Непереведённые доли — напоминания (`pendingTransfers`)
- Подтверждение выпиской (`confirmedShares`): на счёт пришёл «Перевод собственных средств» на сумму доли ±1 ₽ в дату смены … +3 дня → вместо галочки «подтверждено выпиской»; один перевод подтверждает одну долю
- Отмеченная, но не подтверждённая доля прибавляется к остатку своего счёта (`unconfirmedShares` → `balanceOf`, подпись «+ N ₽ «Перевёл»»), для «Турции», «Жизни» и «Одежды и ухода» одинаково. Подтвердилась — уже в остатке по выписке, без двойного счёта. Введённый вручную остаток после даты дохода — доля уже в нём
- Доходы до даты старта (05.10.2026) в конверты не идут, только в аналитику
- Сверка по выпискам (`transferCheck`): входящие «Переводы собственных средств» на счёт с даты старта по конец его выписки против доли доходов → «всё переведено» или «недоперевёл N ₽»

**Режим «Турция»** (`turkeyLogic.ts`, `TurkeyCard.tsx`)
- Старт 0 ₽ с 05.10.2026, срок 31.07.2027, сумма цели — в настройках. Прогресс = рост остатка счёта «Турция» с даты старта (проценты в плюс); остаток уже включает отмеченные «Перевёл», но не подтверждённые выпиской доли (`turkeyAdded` → `balanceOf`)
- Прогноз «Успеваю ли»: темп = средняя в Турцию за неделю за последние 4 недели; если с даты старта меньше 2 недель — по плану: % Турции × цена смены × смен в месяц (по умолчанию 15), с подписью «уточнится». Отмеченные будущие смены (без дохода) — каждая по доле Турции от цены смены, после последнего отмеченного дня — по темпу. «Не вышел» не считается сменой и снижает темп
- Одной фразой (`forecastText`, `ForecastPhrase.tsx`, иконки lucide, без эмодзи): «Успеваешь, запас ~N ₽» / «Впритык» (запас < 5 % цели) / «Не хватит ~N ₽ — это +K смен в месяц»

**Режим «Месяц»**
- «Можно потратить» = остаток «Жизнь» + карта; под ним остатки всех 4 счетов с подписью «по выписке на …» / «введено …»
- Месяц (стрелки, «Последний месяц»; при открытии — последний месяц с данными): доход за смены с долями и галочками + форма «Получил за смену» → сверка переводов → «Доход и траты за месяц»: доля «Жизнь» (50 % дохода) против трат с карты кроме «Одежды и ухода», доля «Одежда и уход» против трат этой категории (в месяце старта и доход, и траты — с даты старта, подпись «считается с 05.10», `monthStart`) → траты по категориям (в месяце старта — тоже с даты старта) (у категорий с лимитом — полоски, превышение красным; лимиты меняются, удаляются, добавляются) → «Операции по карте» (свёрнуто, категория меняется; на телефоне категория — отдельной строкой)
- Пустое состояние — карточка «С чего начать» (выписка карты → выписки счетов-конвертов → настройки)

**Настройки** (шестерёнка): доли 50/40/10, цена смены (5000), смен в месяц по плану (15), цель (сумма, «считаю с», срок), список знакомых счетов с выбором типа

**Выписки Ozon Банка (PDF, читаются в браузере через pdfjs-dist)**

Без этого Safari на iPhone падал с «undefined is not a function (near '…e of t…')»: обычная сборка pdf.js 6 использует функции, которых там нет. Проверка: удалить эти функции в странице и в воркере — выписка должна читаться
- Операция начинается с «ДД.ММ.ГГГГ ЧЧ:ММ:СС», дальше номер документа, назначение (может быть на нескольких строках), сумма «+ 1 234.56 ₽» / «- 1 234.56 ₽». Шапки таблицы и номера страниц пропускаются
- Особенности настоящего PDF Ozon (проверено на реальной выписке): сумма стоит в двух колонках (две копии в строке — из назначения убираются все); 11-значный номер документа переносится — последняя цифра в начале 2-й строки (приклеиваем к номеру); номер страницы — отдельная строка внизу (pdfText ставит метку конца страницы, число перед ней выбрасывается); строка таблицы может разорваться между страницами; переносы внутри слов/дат склеиваются без пробела. В назначении перевода между своими счетами номера счёта-получателя нет
- Сверка с «Итого зачислений / Итого списаний»: не сходится — ошибка, импорт заблокирован; строк «Итого» нет — предупреждение. У счетов-конвертов ещё: входящий остаток + операции = исходящий
- Повторная загрузка не дублирует: ключ операции — номер счёта + номер документа + дата и время (`src/utils/operationKey.ts`); та же выписка обновляет уже загруженные операции. Операции всех учитываемых счетов хранятся вместе, траты и доход считаются только по карте (`kindOf`). Выписка без номера счёта — только как карта. Суммы — в копейках (целые числа)
- Выписки загружаются в любом порядке (проверено на настоящих выписках за 04.07–04.10.2026: карта — 200 операций, 22 смены по доходу; «Турция» — 42 операции, остаток сходится)

**Категории операций** — вычисляются, а не хранятся: сначала своё правило для магазина, потом встроенные, иначе «Прочее»
- YANDEX*…*EDA, BURGER, Vkusnoitochka, SHAVERMA → «Кафе»; YANDEX*…*GO → «Такси»; AVTOMIG / ETK / GPP → «Проезд»
- MAGNIT / KRASNOE / Тандер / EVROPA / LINIYA → «Продукты»; МОБИ.ДЕНЬГИ / МУРМАНСКИЙ РАСЧЕТНЫЙ / DUKPEJ → «Игры»
- «Одежда и уход» (одежда, косметика, барбершоп; встроено: BARBER, GOLDAPPLE, ЛЭТУАЛЬ, RIVGOSH) — тратится со счёта «Одежда и уход»
- «Оплата за усл. по дог.» → «Доход: склад» (доход только с плюсом); «Перевод собственных средств» → «Перевод между счетами»; «Выплата/Начисление процентов» → «Проценты». Доход, переводы и проценты — не траты
- Траты категории считаются «чистыми»: списания минус поступления той же категории (возврат, СБП, кешбэк); если поступлений больше — 0, не минус
- Сменил категорию вручную → запоминается правило для магазина. Ключ магазина — только буквы назначения: слова, где цифр ≥ 40 % (номера карт, даты, время, суммы, ID СБП), выкидываются (`src/utils/statementText.ts`). `YANDEX*4121*GO` и `YANDEX*5530*GO` — один магазин; у СБП-перевода ключ — получатель

**Связь со «Сменами»** (логика в `moneyLogic.ts`, «Смены» её только вызывают)
- В итогах месяца: «Пропусков: K — это −X ₽, из них −Y ₽ на Турцию» (K × цена смены, × процент Турции)
- Если в месяце есть отработанные смены и доход — «по факту в среднем Z ₽ за смену»

**Хранение и миграция** — всё в `planner.money` = `{ settings: { split, shiftPay, shiftsPerMonth, goal, limits, customCategories }, transactions, rules, accounts: { номер: { kind, periodStart, periodEnd, balances: [{ date, kop }] } }, manualIncome, transfers, manualBalances }`. Старая копилка `planner.savings` убрана: при загрузке из неё берётся сумма цели, ключ удаляется; старый счёт `savings` становится «Турцией» (его остаток — точка отсчёта), категория «Одежда» → «Одежда и уход» (правила и лимиты). Починка старых операций — `src/storage/moneyMigration.ts` + `mergeTransactions`/`removeSavingsCopies`

### Неделя
- 7 дней с понедельника, у каждого список задач (добавить / отметить выполненной / удалить). Задачи привязаны к дате
- Переключение между неделями и кнопка «Эта неделя»; сверху «выполнено N из M» за неделю
- Дни со сменой подсвечиваются, у «не вышел» — коралловая полоса и плашка со значком ✕, у отгула и выходного — свои плашки. Данные и логику берём из «Смен» (`src/tabs/shifts/schedule.ts`), не дублируем; «Неделя» смены только читает
- **Итог недели** (`weekSummary.ts` + `WeekReviewCard.tsx`) — карточка вверху: в воскресенье открывается сама, в другие дни — кнопкой «Итог недели». Следует за выбранной неделей, так что прошлые итоги листаются стрелками. Цифры берутся из логики других вкладок, не дублируются:
  - смены: отработано / пропущено, «≈ X ₽ по цене смены», цена пропусков (`missedCost`)
  - деньги: доход за смены недели (`incomeBetween`), сколько добавилось на «Турцию» (`turkeyAdded`)
  - задачи: выполнено N из M
  - привычки: сколько дней отмечено за неделю и текущая серия (автопривычка — сколько смен)
  - поля «Что получилось» и «Что мешало» — сохраняются по неделям (ключ — понедельник), пустой итог не хранится
- Хранение: `{ tasks: { 'YYYY-MM-DD': [{ id, text, done }] }, reviews: { 'понедельник': { good, bad } } }`

### Смены
- График гибкий, не строгий 2/2. Основной способ — отмечать дни вручную в календаре месяца (переключение месяцев)
- Статусы дня — только они, без времени: смена, «не вышел» (смена была запланирована, но я не пошёл), отгул, выходной. Неотмеченный день = смены нет. Смена всегда стандартная ночная, 22:00–10:00 (`SHIFT_HOURS` в `schedule.ts`)
- Календарь — квадраты `DaySquare`: отработал — заливка акцентом, смена впереди — контур, «не вышел» — коралловый ✕, отгул/выходной — свои цвета, сегодня — белая обводка. В клетке — число и короткая подпись; на узком экране (≤ 640 px) только вид квадрата (как в легенде `DayLegend`)
- Помощник «Заполнить 2/2 с даты… по дату…» — один раз проставляет смены (2 дня смена, 2 дня нет), уже отмеченные дни не трогает
- Итог за месяц: отработано (прошедшие смены), впереди, не вышел, отгулы
- Хранение: `{ days: { 'YYYY-MM-DD': { status } } }`. В старых данных у смены было время (`time`) — при загрузке и из бэкапа оно отбрасывается. Совсем старый формат (firstShiftDate + overrides) переводится в новый: автографик 2/2 разворачивается в отмеченные смены от первой смены до «сегодня + год», ручные правки переносятся как есть

## Синхронизация (Supabase)
- Ключи: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` — локально в `.env` (в .gitignore, образец — `.env.example`), для деплоя — в GitHub Secrets (workflow передаёт их в сборку). Ключей нет — синхронизация выключена, статуса в шапке нет. Публичный ключ попадает в код сайта — это нормально, чужие данные защищает RLS
- Таблица `planner_data`: `user_id` (= `auth.uid()`) + разделы в формате бэкапа (jsonb): `money` (деньги без настроек), `shifts`, `week`, `habits`, `settings` (настройки денег), у каждого `*_updated_at`. RLS: читать/писать/удалять только владелец, у гостя (anon) прав нет
- Вход: email + пароль (Supabase Auth), сессию хранит сам Supabase. «Выйти» — только на этом устройстве, данные остаются
- Когда: при открытии и входе, через 2 с после изменения (`writeJson` сообщает о сохранении через `onWrite`), при возврате на вкладку и при появлении сети. Офлайн изменения лежат на устройстве и уходят, когда сеть появится
- Что изменилось — по отпечатку раздела (`hashOf`), служебное — в `planner.sync` (`storage/syncStorage.ts`, в бэкап не идёт). Конфликт решается по разделу: новее `updated_at` — побеждает. Отправляемый `updated_at` всегда новее облачного (`pushAt`)
- Данные из облака проверяются тем же кодом, что бэкап (`parseBackupData`), после записи вкладка пересоздаётся (`dataVersion`)
- Первый вход на устройстве: в облаке пусто — туда уходят данные устройства; на устройстве пусто или данные совпадают — берём облако; есть и там, и там — карточка «Какие данные оставить?»
- Статус в шапке: «синхронизировано» / «синхронизация…» / «офлайн» / «не вошёл» (+ «ошибка синхронизации» с повтором через 30 с, «нужен ответ»)

## PWA и публикация
- Манифест в `vite.config.ts`: название «Планировщик», иконки `public/pwa-192.png`, `pwa-512.png`, `pwa-maskable-512.png` (Android), `apple-touch-icon.png` (iPhone), `favicon.svg` — синий акцент и белый календарь с галочкой. Исходник иконок — SVG в стиле дизайна, PNG генерируются скриптом (sharp) вне проекта
- `theme-color` в `index.html` и цвета манифеста — фон страницы #08080c (тема одна, тёмная)
- Офлайн: service worker кэширует весь сайт (страница, js/css, шрифты woff2, иконки, воркер pdf.js — лимит 3 МБ на файл)
- Обновление: `registerType: 'prompt'` — новая версия скачивается в фоне, внизу плашка «Доступна новая версия — Обновить» (`src/components/UpdatePrompt.tsx`); без нажатия не перезагружается
- Проверка PWA — только на сборке: конфигурация запуска `preview` (`npm run build`, потом `npm run preview`). В `npm run dev` service worker не работает
- Адрес: `base` в `vite.config.ts` берётся из `BASE_PATH` (локально `/`). GitHub Actions (`.github/workflows/deploy.yml`) собирает с `BASE_PATH=/<репозиторий>/` и публикует на GitHub Pages при пуше в `main`. В Git Bash на Windows для локальной проверки такой сборки нужен `MSYS_NO_PATHCONV=1`, иначе путь испортится
- Сайт: https://morphabuse.github.io/life-planner/ — репозиторий https://github.com/morphabuse/life-planner (публичный). Каждый пуш в `main` публикует новую версию
- Ветки: `main` — публичная (история начата заново одним коммитом «Первая публикация», без личных данных). `private-history` — старая полная история, в ней есть номер счёта и цифры карт: **только локально, никогда не пушить** (`git push` — только `main`, не `--all`)
- Перед каждым пушем — не добавлять в код и документы личные данные: ФИО, номера счетов и карт, примеры из настоящих выписок (в примерах — условный счёт 40817810000000000000)
- Данные хранятся в браузере отдельно для каждого адреса: на опубликованном сайте данных сначала нет — перенос через «Скачать бэкап» → «Загрузить бэкап»

## Как работаем
- Маленькие задачи, по одной фиче за раз
- Сначала показать план изменений, потом писать код
- После каждого рабочего шага — git-коммит с понятным сообщением на русском
- Код и комментарии понятные: я учусь, объясняй, что сделал
- Одна сессия Code = одна большая задача. Закончил — коммит, пуш, следующая задача в новой сессии (правила проекта — в этом файле, держи его актуальным)
- Логику денег проверяй на настоящих выписках из `private/`, а не только на сгенерированных: у Ozon Банка шапки выписок карты и накопительных одинаковые, выписка отстаёт на ~1 день, зарплата за смену приходит двумя платежами
- Доход и траты в аналитике всегда считаются за один и тот же период
- Дизайн сначала согласуем макетом (Claude Design), потом переносим в код по токенам
