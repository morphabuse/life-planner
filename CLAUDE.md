# Планировщик жизни (рабочее название)

Личный сайт-планировщик для одного пользователя (Ваня). Вырос из трекера «Копилка на Турцию».
Пользуюсь в основном с компьютера. Регистрации и аккаунтов нет.

## Стек
- Vite + React + TypeScript
- Данные: localStorage + кнопки «Экспорт / Импорт JSON» для бэкапа
- Без бэкенда в версии 1
- Стили: обычный CSS (модули), без тяжёлых UI-библиотек
- Шрифт Inter (`@fontsource/inter`), иконки `lucide-react`
- PWA: `vite-plugin-pwa` — сайт ставится на телефон как приложение и работает офлайн

## Структура
- Сверху переключаемые вкладки: «Сегодня» (открывается по умолчанию), «Деньги», «Неделя», «Смены», «Привычки». На узком экране выбранная вкладка сама прокручивается в видимую часть полосы
- `src/tabs/` — по папке на вкладку (`today/`, `money/`, `week/`, `shifts/`, `habits/`)
- `src/storage/` — вся работа с localStorage в одном месте (компоненты не трогают localStorage напрямую)
- `src/types.ts` — общие типы данных
- `src/styles/tokens.css` — дизайн-токены, `src/styles/global.css` — сброс, шрифт, фокус
- `src/components/ui/` — единые компоненты интерфейса (Button, Card, Collapsible, Input, Select, Textarea, ProgressBar, Badge/StatusDot)
- `private/` — личные файлы (настоящие выписки для тестов). В `.gitignore`, никогда не коммитим. Тестовые PDF брать только отсюда

## Дизайн
Спокойный, единый для всего сайта. Скриншоты-образцы: `docs/screenshots/` (светлая и тёмная тема).

**Токены — единственный источник значений**
- Все цвета, отступы, радиусы, размеры шрифта и анимации — только `var(--…)` из `src/styles/tokens.css`. Никаких hex/rgb «на месте» в компонентах. Нужен новый цвет — добавь токен (в светлую тему и в оба блока тёмной)
- Отступы — шаг 4/8 px: `--space-1` (4) … `--space-12` (48). Произвольных `13px` нет
- Радиусы: `--radius-sm` (ячейки, плашки), `--radius-md` (кнопки, поля), `--radius-lg` (карточки)

**Палитра**
- Нейтральные тёплые серые (`--color-bg`, `--color-surface`, `--color-surface-muted`, `--color-surface-raised`, `--color-border*`, `--color-text*`) + один акцент — спокойный синий (`--color-accent*`)
- Статусы приглушённые, у каждого фон/текст/рамка: `--status-shift-*`, `--status-missed-*`, `--status-leave-*`, `--status-off-*`, `--status-danger-*` (ошибки, превышение лимита), `--status-success-fg` (положительные суммы)
- Нельзя: градиенты, кислотные цвета, эмодзи в интерфейсе, тени на карточках и кнопках (карточки — тонкая рамка)

**Тема**
- Светлая и тёмная, по умолчанию как в системе. Переключатель в шапке (система → светлая → тёмная), выбор в `planner.theme` (в бэкап не идёт)
- Тёмная тема — те же имена токенов с другими значениями (`[data-theme='dark']` и `@media (prefers-color-scheme: dark)`)

**Типографика** (Inter, у всех цифр `tabular-nums`)
- Заголовок раздела — `--text-lg` (20), полужирный; заголовок карточки — `--text-md` (16), полужирный
- Текст — `--text-base` (15); подписи и подсказки — `--text-sm` (13), цвет `--color-text-muted`; мелкое в ячейках — `--text-xs` (12)
- Крупные числа (итоги) — `--text-xl` (28) или `--text-lg`

**Компоненты** — новые экраны собираются из `src/components/ui`, свои кнопки/поля не делаем
- `Button`: `primary` — одно главное действие в форме; `secondary` — обычные; `text` — тихие («Изменить», «Отмена», удаление). Размеры `sm`/`md`. Кнопка-иконка — `iconOnly` + обязательный `aria-label`. Переключатель — `aria-pressed`
- `Card`: заголовок, подзаголовок, действия справа; `compact` для списков карточек
- `Collapsible`: свёрнутая карточка (`<details>`), заголовок + подзаголовок видны всегда, содержимое по клику; `id` — чтобы раскрыть кодом
- `Input`: подпись сверху, подсказка/ошибка снизу; без подписи — нужен `aria-label`. У числовых полей `step="1"` (иначе браузер молча не отправит форму с «неровным» числом)
- `Textarea`: многострочное поле в стиле Input, подпись сверху, растягивается вниз
- `Select`: выпадающий список в стиле Input, размеры `sm`/`md`; `className` задаёт ширину обёртки
- `ProgressBar` (`tone="danger"` — превышение), `Badge` (тона neutral/accent/shift/missed/leave/off/danger), `StatusDot` для легенд
- Иконки lucide 14–18 px, только где помогают понять действие (стрелки, добавить, удалить, закрыть, тема, бэкап)

**Раскладка и поведение**
- Шапка: название слева, вкладки-сегменты, справа бэкап и тема (кнопки-иконки с подсказкой) — на компьютере в одну строку. На узком экране (≤ 640 px): название и кнопки — первая строка, вкладки — вторая на всю ширину и прокручиваются по горизонтали
- Контент по центру, ширина не больше `--content-max-width` (880 px), между карточками `--space-4`, внутри карточки `--space-6`
- Hover/focus — плавно, `--transition-fast` (150 мс). Фокус с клавиатуры всегда виден (`:focus-visible`, рамка `--color-focus`)

## Вкладки версии 1
### Сегодня (`src/tabs/today/`)
Главное на один экран: на компьютере (1280×800) — без прокрутки, две колонки; на телефоне — одна. Своих данных нет, только собирает чужое — логику не дублируем:
- Смена сегодня или завтра: время и подсказка по сну (`getEntry`/`findNextShift` из `schedule.ts`, `sleepTips` из `sleep.ts`). Если сегодня и завтра смен нет — «Ближайшая — …»
- Задачи на сегодня — те же, что в «Неделе» (`planner.week`, `addTask`/`toggleTask` из `weekLogic.ts`): галочки и быстрое добавление
- Привычки на сегодня — отметка в один клик (те же данные, что во вкладке «Привычки»), рядом «N подряд»; автопривычка «Смены без пропусков» — строкой текста
- Одна строка про деньги: «Турция: X из Y ₽ · N смен до цели» (`calcSummary` + `shiftsToGoal`)

### Привычки (`src/tabs/habits/`)
- По умолчанию: «30 минут кода», «Английский», «Лёг вовремя». Можно добавлять, переименовывать, убирать в архив и возвращать (отметки сохраняются)
- У каждой — текущая серия дней и рекорд, сетка за последние 8 недель (колонка = неделя, строка = день с понедельника). Клик по клетке прошлого дня ставит/снимает отметку (если забыл)
- Серия: дни подряд с отметкой. Сегодня ещё не отмечено — серия со вчера жива. Не отмечено ни сегодня, ни вчера — серия 0 и «Начни новую серию». Без красных «провалов»: неотмеченный день — просто нейтральная клетка
- Автопривычка «Смены без пропусков» не хранится и вручную не отмечается: считается из «Смен» — смены подряд без «не вышел» (дни без смены серию не прерывают; сегодняшняя смена ещё не считается, «не вышел» сегодня — уже пропуск)
- Логика — `habitsLogic.ts` (без React). Хранение: `planner.habits` = `{ habits: [{ id, name, archived }], marks: { id: ['YYYY-MM-DD', …] } }`

### Деньги (бывшая «Копилка»)
Порядок на экране: цель и прогресс копилки (отложено, осталось, «N смен до Турции», сверка с остатком счёта) → большая зона «Перетащи PDF выписки сюда или выбери файл» (drag & drop) → месяц: конверты, лимиты, операции → свёрнутые блоки «Пополнить копилку вручную», «История копилки», «Настройки».
- При открытии показывается последний месяц, где есть данные (а не пустой текущий); рядом подпись «данные по ДД.ММ.ГГГГ» (конец периода последней выписки). Кнопка «Последний месяц»
- Пустое состояние (нет ни операций, ни записей копилки): вместо карточек с нулями — карточка «С чего начать» из 3 шагов: выписка карты → выписка накопительного → проверь цену смены (кнопка раскрывает «Настройки»)

**Копилка**
- Цель: Турция, август 2027, целевая сумма. Записи копилки: дата + сумма со знаком (пополнение +, снятие −), история списком
- Показывать: сколько отложено, сколько осталось, сколько нужно откладывать в месяц до даты цели, прогресс-бар
- «До Турции осталось N смен» = остаток цели / (процент Турции × цена смены), округление вверх

**Настройки** (`planner.money.settings`)
- Распределение каждого дохода «Доход: склад»: 50% жизнь / 40% Турция / 10% одежда (меняется, в сумме 100)
- Сколько я получаю за смену — по умолчанию 5000 ₽

**Конверты за месяц** — положено (доход × процент), потрачено/отложено, остаток
- «Жизнь» — все траты, кроме «Одежды» и «Перевода между счетами»
- «Одежда» — категория «Одежда»
- «Турция» связан с копилкой: «должно быть отложено X (40% дохода), отложено Y (пополнения копилки за месяц)»

**Лимиты внутри «жизни»** — по умолчанию кафе 2000, такси 1000, игры 1500; полоски, превышение красным; можно менять, удалять и добавлять (на любую категорию или новую свою)

**Выписки Ozon Банка (PDF, читаются в браузере через pdfjs-dist)**
- Сборка pdf.js — **legacy** (`pdfjs-dist/legacy/build`) + свои замены `statement/pdfPolyfills.ts` (`Promise.withResolvers`, перебор `ReadableStream` в `for await`) — и в странице, и в своём воркере `statement/pdfWorker.ts` (подключён через `GlobalWorkerOptions.workerPort`). Без этого Safari на iPhone падал с «undefined is not a function (near '…e of t…')»: обычная сборка pdf.js 6 использует функции, которых там нет. Проверка: удалить эти функции в странице и в воркере — выписка должна читаться
- Операция начинается с «ДД.ММ.ГГГГ ЧЧ:ММ:СС», дальше номер документа, назначение (может быть на нескольких строках), сумма «+ 1 234.56 ₽» / «- 1 234.56 ₽». Шапки таблицы и номера страниц пропускаются
- Особенности настоящего PDF Ozon (проверено на реальной выписке): сумма стоит в двух колонках (две копии в строке — из назначения убираются все); 11-значный номер документа переносится — последняя цифра в начале 2-й строки (приклеиваем к номеру); номер страницы — отдельная строка внизу (pdfText ставит метку конца страницы, число перед ней выбрасывается); строка таблицы может разорваться между страницами; переносы внутри слов/дат склеиваются без пробела
- Повторная загрузка той же выписки обновляет уже загруженные операции (если разбор улучшился), новые добавляет. Операции, загруженные старым разбором (в назначении есть «₽»), чинятся автоматически при загрузке данных (`src/storage/moneyMigration.ts`), правила переносятся на новые ключи
- Сверка с «Итого зачислений / Итого списаний»: не сходится — ошибка, импорт заблокирован; строк «Итого» нет — предупреждение
- Повторная загрузка не дублирует: ключ операции — номер счёта + номер документа + дата и время (`src/utils/operationKey.ts`). Счёт обязателен: перевод между своими счетами есть в обеих выписках с тем же документом и временем и разным знаком
- Номер лицевого счёта берётся из шапки («Номер лицевого счёта: № …»), счёт запоминается в `planner.money.accounts` с типом, концом периода и (для накопительного) остатком — при следующей загрузке тип берётся оттуда
- Тип новой выписки — по содержимому: есть «Выплата процентов по счету» и нет «Оплата товаров по карте» → накопительный (шапки карты и накопительного в настоящих выписках одинаковые, слова «накопительный» там нет); запасной признак — «накопительн» в шапке. Перед импортом можно переключить
- Обе выписки загружаются в любом порядке без потерь (проверено на настоящих выписках за 04.07–04.10.2026: 200 операций карты, копилка = исходящему остатку накопительного)
- Карта (основной счёт) → операции сохраняются (суммы в копейках, целые числа). Накопительный счёт / счёт «Турция» → в копилку с галочками предлагаются входящие «Перевод собственных средств» (пополнение), исходящие (снятие, с минусом) и проценты («Выплата/Начисление процентов»); у такой записи есть `importKey`, второй раз не добавится (старые ключи без счёта тоже узнаются). «Исходящий остаток» выписки сверяется с суммой копилки: в предпросмотре и в итогах копилки показывается «сходится» или расхождение
- Счета у меня в Ozon: основной (с картами) — грузим как «Карта»; «Турция» — как «Накопительный счёт» (в копилку); «Свободные деньги», «Одежда и уход», «Скидка» — не грузим (переводы с них видны на основном счёте как «Перевод собственных средств»)

**Категории операций** — вычисляются, а не хранятся: сначала своё правило для магазина, потом встроенные, иначе «Прочее»
- YANDEX*…*EDA, BURGER, Vkusnoitochka, SHAVERMA → «Кафе»; YANDEX*…*GO → «Такси»; AVTOMIG / ETK / GPP → «Проезд»
- MAGNIT / KRASNOE / Тандер / EVROPA / LINIYA → «Продукты»; МОБИ.ДЕНЬГИ / МУРМАНСКИЙ РАСЧЕТНЫЙ / DUKPEJ → «Игры»
- «Оплата за усл. по дог.» → «Доход: склад» (доход считается только с плюсом); «Перевод собственных средств» → «Перевод между счетами»; «Выплата/Начисление процентов» → «Проценты». Доход, переводы и проценты — не траты
- Траты категории считаются «чистыми»: списания минус поступления той же категории (возврат, человек вернул деньги по СБП, кешбэк); если поступлений больше — 0, не минус
- Сменил категорию вручную → запоминается правило для магазина. Ключ магазина — только буквы назначения: слова, где цифр ≥ 40 % (номера карт, даты, время, суммы, ID СБП), выкидываются (`src/utils/statementText.ts`). `YANDEX*4121*GO` и `YANDEX*5530*GO` — один магазин; у СБП-перевода ключ — получатель

**Связь со «Сменами»** (логика в `src/tabs/money/moneyLogic.ts`, «Смены» её только вызывают)
- В итогах месяца: «Пропусков: K — это −X ₽, из них −Y ₽ на Турцию» (K × цена смены, × процент Турции)
- Если в месяце есть отработанные смены и доход из выписки — «по факту в среднем Z ₽ за смену» (доход месяца / отработанные смены)

- Миграция старых данных (`src/storage/moneyMigration.ts` + `mergeTransactions`/`removeSavingsCopies` в `moneyLogic.ts`): операции без счёта (старый ключ) при загрузке выписки карты переезжают под новый ключ (знак берётся из выписки карты); операции накопительного, по ошибке загруженного как карта, убираются — проценты сразу при загрузке данных (счёт запоминается как накопительный), переводы — при загрузке выписки накопительного
- Хранение: копилка — `planner.savings`; остальное — `planner.money` = `{ settings, transactions, rules, accounts }`

### Неделя
- 7 дней с понедельника, у каждого список задач (добавить / отметить выполненной / удалить). Задачи привязаны к дате
- Переключение между неделями и кнопка «Эта неделя»; сверху «выполнено N из M» за неделю
- Дни со сменой подсвечиваются и показывают время смены, у «не вышел» — красная пометка, у отгула и выходного — свои плашки. Данные и логику берём из «Смен» (`src/tabs/shifts/schedule.ts`), не дублируем; «Неделя» смены только читает
- **Итог недели** (`weekSummary.ts` + `WeekReviewCard.tsx`) — карточка вверху: в воскресенье открывается сама, в другие дни — кнопкой «Итог недели». Следует за выбранной неделей, так что прошлые итоги листаются стрелками. Цифры берутся из логики других вкладок, не дублируются:
  - смены: отработано / пропущено, «≈ X ₽ по цене смены», цена пропусков (`missedCost`)
  - деньги: доход «Доход: склад» по выписке за неделю (`incomeBetween`), сколько ушло в копилку (пополнения − снятия)
  - задачи: выполнено N из M
  - привычки: сколько дней отмечено за неделю и текущая серия (автопривычка — сколько смен)
  - поля «Что получилось» и «Что мешало» — сохраняются по неделям (ключ — понедельник), пустой итог не хранится
- Хранение: `{ tasks: { 'YYYY-MM-DD': [{ id, text, done }] }, reviews: { 'понедельник': { good, bad } } }`

### Смены
- График гибкий, не строгий 2/2. Основной способ — отмечать дни вручную в календаре месяца (переключение месяцев)
- Статусы дня: смена, «не вышел» (смена была запланирована, но я не пошёл), отгул, выходной. Неотмеченный день = смены нет
- У смены есть время: по умолчанию 22:00–10:00, быстрые варианты 17:00–01:00 и 17:00–10:00, можно своё. Если конец ≤ начала — смена заканчивается на следующий день. В календаре время показывается коротко («22–10»)
- Помощник «Заполнить 2/2 с даты… по дату…» — один раз проставляет смены (2 дня смена, 2 дня нет), уже отмеченные дни не трогает
- Итог за месяц: отработано (прошедшие смены), впереди, не вышел, отгулы
- Подсказка по сну под ближайшей сменой зависит от начала смены:
  - начало в 20:00 и позже — накануне ночной сон 23:45–9:00, в день смены дневной сон 3 часа (2 цикла по 90 мин) с подъёмом за 2 часа до начала и 15 минутами на засыпание (для 22:00 — «лечь 16:45, сон 17:00–20:00»)
  - начало раньше 20:00 — выспаться ночью, встать не раньше 9:00–10:00, дневной сон не нужен
  - «вторая ночь подряд»: если смена накануне идёт до 06:00 или позже — ночного сна не будет; если кончилась раньше (например, в 01:00) — после неё сразу спать
- Хранение: `{ days: { 'YYYY-MM-DD': { status, time? } } }`. Старый формат (firstShiftDate + overrides) автоматически переводится в новый: автографик 2/2 разворачивается в отмеченные смены 22:00–10:00 от первой смены до «сегодня + год», ручные правки переносятся как есть

- Кнопки «Скачать бэкап» / «Загрузить бэкап» в шапке, файл `planner-backup-ГГГГ-ММ-ДД.json`, проверка файла и вопрос перед перезаписью

## PWA и публикация
- Манифест в `vite.config.ts`: название «Планировщик», иконки `public/pwa-192.png`, `pwa-512.png`, `pwa-maskable-512.png` (Android), `apple-touch-icon.png` (iPhone), `favicon.svg` — синий акцент и белый календарь с галочкой. Исходник иконок — SVG в стиле дизайна, PNG генерируются скриптом (sharp) вне проекта
- `theme-color`: в `index.html` два тега (светлая/тёмная системная тема, цвет поверхности шапки); при теме, выбранной вручную, `src/utils/theme.ts` ставит в оба цвет токена `--color-surface`
- Офлайн: service worker кэширует весь сайт (страница, js/css, шрифты woff2, иконки, воркер pdf.js — лимит 3 МБ на файл)
- Обновление: `registerType: 'prompt'` — новая версия скачивается в фоне, внизу плашка «Доступна новая версия — Обновить» (`src/components/UpdatePrompt.tsx`); без нажатия не перезагружается
- Проверка PWA — только на сборке: конфигурация запуска `preview` (`npm run build`, потом `npm run preview`). В `npm run dev` service worker не работает
- Адрес: `base` в `vite.config.ts` берётся из `BASE_PATH` (локально `/`). GitHub Actions (`.github/workflows/deploy.yml`) собирает с `BASE_PATH=/<репозиторий>/` и публикует на GitHub Pages при пуше в `main`. В Git Bash на Windows для локальной проверки такой сборки нужен `MSYS_NO_PATHCONV=1`, иначе путь испортится
- Сайт: https://morphabuse.github.io/life-planner/ — репозиторий https://github.com/morphabuse/life-planner (публичный). Каждый пуш в `main` публикует новую версию
- Ветки: `main` — публичная (история начата заново одним коммитом «Первая публикация», без личных данных). `private-history` — старая полная история, в ней есть номер счёта и цифры карт: **только локально, никогда не пушить** (`git push` — только `main`, не `--all`)
- Перед каждым пушем — не добавлять в код и документы личные данные: ФИО, номера счетов и карт, примеры из настоящих выписок (в примерах — условный счёт 40817810000000000000)
- Данные хранятся в браузере отдельно для каждого адреса: на опубликованном сайте данных сначала нет — перенос через «Скачать бэкап» → «Загрузить бэкап»
